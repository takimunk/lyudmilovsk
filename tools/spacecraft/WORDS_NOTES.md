# «Ласточка»: the words and the panel's printed labels

Everything the flight home from Europa says or prints, in ru / en / ja (docs/spacecraft.md, the localization skill).

| File | What |
|---|---|
| `tools/spacecraft/strings.json` | THE SOURCE: every word, `{"key": {"ru", "en", "ja"}}` |
| `tools/spacecraft/strings.py` | writes the tables; `--check` (CI), `--list` |
| `unreal/Lyudmilovsk/Content/Localization/spacecraft/strings_{ru,en,ja}.json` | generated, never edited by hand |
| `tools/spacecraft/labels.json` | the plates (plate id -> string keys, class), fonts, and the layout that was drawn |
| `tools/spacecraft/labels.py` | draws `textures/spacecraft/T_SC_labels_{ru,en,ja}.png`; `--check`, `--auto`, `--boxes`, `--lang` |
| `localization/voice.json` | speaker `flightauto` and the ten `line.hero.flight_*` directions; voiced 2026-11-28 in ru/en/ja (69 takes, 7 929 characters: ~$0.79 on fal at $0.10 per 1000, request ids in each `audio/voice/<lang>/<key>.json`) |

Change a word: edit `strings.json`, then `python3 tools/spacecraft/strings.py && python3 tools/spacecraft/labels.py`,
then `python3 tools/check_localization.py` (its 70 "item ... has no icon" problems are older and not this feature's).

## No C++ registration
`LyudText` (`Private/LyudText.cpp`, `Table()`) merges every `Content/Localization/<sub>/strings_<lang>.json` it finds, so
the `spacecraft` folder loads by itself; `tools/check_localization.py` checks it the same way. `LyudText::Get(TEXT("ui.flight.sit"))`
just works. None of these keys exists in the hand-written tables or another sub-folder (`strings.py --check` enforces it).

**The book**: `flight.book.title`, `flight.book.1` .. `flight.book.5` (the page, one entry per key, in order),

**CRT phases `flight.phase.*`**: `parked prelaunch ascent coast approach entry chute splash afloat` (the model's phase ids).

**The automatic voice `flight.auto.*`** (13; the subtitle key): `ready launch cutoff weightless burn half approach sep entry
blackout chute splash home`. The same text is generated as `line.flightauto.<id>.1` so the voice tool can voice it:

## Choices to know about (none is canon; all are one-line changes in strings.json)
- Switch ids in the words are `power air gyro seal arm` (lamp ids stay `power air gyro hatch armed` as given).
- English keeps the name "Lastochka" (docs/spacecraft.md); Japanese is ツバメ号; the hero says «Ласточка» / "Lastochka" / ツバメ.
- The maker's plate: «Людмиловский приборный завод», «Аппарат спускаемый СА-1», «Зав. № 000001», «1968 г.». The plant is
  invented; 1968 is the year the town's existing texts mention most. Both are flavour, not story: change or drop freely.
- The log in the stowage net has no author and explains nothing; it only says the island is "where it should be", that the
  second couch is kept free, and how to launch. Nothing in it or in the hero's lines names the simulation.
- `ДМП` on the Russian lamp `jets` is the real abbreviation (двигатели мягкой посадки).

## The label atlases
`T_SC_labels_<lang>.png`: 1024 x 1024, 8-bit grey, white on black (a mask: tint or make emissive in the material; import as
a linear single-channel texture, e.g. `TC_Grayscale`, sRGB off; three of them are about 0.3 MB on disk, 1 MB each in memory
uncompressed). Runtime: `LyudText::LoadTexture` wants `/Game/<Folder>/Localized/<lang>/<Name>`, so import them as
`/Game/Spacecraft/Localized/<lang>/T_SC_labels` (or load `T_SC_labels_<lang>` by `LyudText::Language()` directly).
Face: `fonts/MPLUS1p-Bold.ttf` (OFL, already in the repo; it has Latin, Cyrillic and Japanese: `labels.py` fails on a
missing glyph), drawn condensed (x0.80 ru/en, x0.92 ja) with letter spacing, since `fonts/` has no condensed technical face.
65 plates: `lamp_<id>` (24), `inst_<id>` (16), `sw_<id>` (9), `mark_<id>` (6), `unit_<id>` (8), `nameplate`, `dataplate`.

**The layout is data.** Right now `Content/Spacecraft/kit.json` does not exist, so the plates are auto-packed and the
rects are in `labels.json` -> `layout.rects` (`{plate id: [x, y, w, h]}`, px of 1024, origin top left; UV = px / 1024).
The Blender kit can simply read those rects, OR define its own:

**After the kit lands**: `python3 tools/spacecraft/labels.py` (then `--check`). If kit.json has a label plate list
(`labels` | `label_plates` | `label_rects` | `plates`, top level or under `atlas` / `textures` / `labels_atlas`; entries
`[x, y, w, h]`, or `{"rect": [...]}`, or `{"uv": [u0, v0, u1, v1]}` with V down, px or 0..1 fractions; the header of
labels.py has the full list) it is used instead of the auto layout, the text is re-fitted to every rect (shrunk, then
narrowed, never clipped) and `layout.source` becomes `"kit"`. Plate ids should be the ones above; a kit plate with another
id needs `"key": "flight...."` (or `"keys": [...]` for lines) in its kit entry, or an entry in `labels.json` `plates`.
The run reports kit plates without words, plates without a kit rect, overlaps, and anything squeezed below x0.55 or
smaller than ~6 px capitals. If the kit's schema is something else, the only function to touch is `kit_plates()`.
`--auto` forces the built-in layout; `--boxes` draws the rect outlines for a proof (do not ship that image).
